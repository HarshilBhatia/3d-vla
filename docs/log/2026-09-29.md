VideoPooled's robustness — an arm that barely uses its history matches it. The
robustness looks like a property of the video training and architecture. The
register test (7) is the outstanding check.

## Issues found

- **Automatic checkpoint evals never fired.** The trainer called the ladder
  launcher before the async saver had written `interm_step_*.pth`. Fixed in
  `83af810` (flush first), but only jobs started after the fix use it.
  - `scripts/eval/submit_pending_ladders.sh` now runs every 2 hours in a
    `nohup` loop (log: `logs/eval/submit_pending_ladders.log`).
  - The ledger skips checkpoints that were already submitted, so repeats are safe.
- **Video ladders ran with K=1.** `visual_num_history` is eval-owned and the
  ladder recipes didn't set it, so evals used the one-frame default. Fixed in
  `41fe8ee` by adding `visual_num_history=5` to the video ladder recipes.
  - The old FullPatch ladder mixed settings (s170000 at K=1, s80000 at K=5), so
    its 76.7 "best FullPatch" gate is unreliable.
  - Same cause behind VideoPooled's "83.3 at 84k"; a K=5 re-ladder was
    submitted (3974886–3974895, method `video-pooled-k5`).
- **grogu-4-3 is broken (24 Sept):** CUDA fails to initialise there. About 330
  robustness cells and 82 ladder cells wrote no result, yet the eval wrapper
  still exits 0, so Slurm marked them COMPLETED. The node is now excluded in
  `scripts/eval/online_eval_plan.slurm` (commit `b1b2f7e`) and only the missing
  cells were resubmitted.
- **Experiment 6 crash:** a validation DataLoader worker segfaulted at step 68k.
  If it recurs at the next validation pass (every 4k steps), it's systematic.
- **FullPatch `nan`** in the logged total training loss: the individual terms
  are fine and the parent run shows the same thing, so it's a logging quirk.
- **Launcher ARM-list brace bug**, fixed in `069ef48` (hit the EMA submissions).

## Cluster practice settled this week

- **Never cancel a running job.** Only cancel PENDING copies.
- 4-GPU jobs need `--mem=400G`; 256 GB was killed by the host-memory limit
  (dataloader workers plus the video cache).
- Long runs are queued **both ways** — single-node 4 GPU and 4 nodes × 1 GPU —
  and whichever starts first wins:
  - `scripts/train/race_twins.sh` / `race_many.sh` cancel the other form's
    still-pending jobs;
  - `scripts/train/claim_run.sh` stops a second job training in the same run
    directory;
  - the launcher resumes from the run's own `last.pth` whenever one exists.
- Multinode preflight is loosened for the small models (`max_node_load` 0.9,
  `min_busbw` 1.0); ~5M trainable parameters make cross-rack bandwidth
  sufficient.
